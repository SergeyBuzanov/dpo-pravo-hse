# Центр ДПО · Факультет права НИУ ВШЭ

Статический сайт центра дополнительного профессионального образования факультета
права НИУ ВШЭ: лендинги, каталог программ и локальная админка для его обновления.

## Страницы

| Файл | Что это |
|---|---|
| `index.html` | Главный лендинг (Design-версия) |
| `Каталог программ.html` | Витрина программ ДПО: карточки со ссылками на hse.ru, фильтры по типу и формату |
| `privacy.html` | Политика обработки персональных данных (152-ФЗ) |
| `404.html` | Страница «такой страницы нет» (отдаётся nginx при ошибке 404) |
| `admin.html` + `admin-server.js` | Локальная админка: обновление каталога и аналитика |

## Обновление каталога программ

Каталог тянет данные из живого каталога hse.ru (факультет права, `orgUnit=22753`).

**Из терминала:**
```bash
node update-catalog.js
```

**Через админку (кнопка «Актуализировать с hse.ru»):**
```bash
node admin-server.js
# затем открыть http://127.0.0.1:5178/admin.html
```
Логин/пароль печатаются в терминал при первом запуске и хранятся в
`.admin-credentials.json` (в git не попадает). Сервер слушает только `127.0.0.1`.

Скрипт тянет **только актуальные** программы (каталог hse.ru без `onlyActual=0`),
разбирает встроенный JSON, обновляет карточки, фильтры, дату и Schema.org
`Course` (JSON-LD). Node 18+, npm-зависимостей нет.

**Админка дополнительно:**
- **ручной редактор программ** (добавить / править / удалить / lock от перезаписи hse.ru);
- **ежедневное автообновление** каталога, пока запущен `admin-server.js` (время настраивается);
- диагностика файлов/маркеров/hse.ru, экспорт JSON;
- **менеджерская аналитика**: посетители, время на сайте, страницы, маршруты,
  интерес к программам, источники, устройства, отказы, часы активности
  (вкладка «Аналитика»; сбор после согласия на cookies через `js/site-analytics.js`,
  хранение в `.analytics/`).

Хранилище программ: **`.catalog-data.json` – он в репозитории**. Из него
`scripts/build-program-pages.js` собирает 26 страниц в `programs/`, а они тоже
закоммичены: без данных их нельзя было бы воспроизвести на чистой машине.
Внутри только публичный каталог hse.ru, доступов и персональных данных там нет.
Наружу файл не отдаётся: он вне белого списка и в nginx, и в превью-сервере.

Обновление каталога меняет этот файл – так и задумано, правки видны в истории
git. После обновления пересоберите страницы и закоммитьте оба изменения:

```bash
npm run update-catalog   # тянет hse.ru, обновляет .catalog-data.json и страницы
git add .catalog-data.json programs/ sitemap.xml "Каталог программ.html"
```

Расписание автообновления: `.catalog-schedule.json` (в git не попадает, оно
локальное).

**Публичный превью-сервер и нагрузочный тест** (симуляция >2000 пользователей):
```bash
npm run serve        # http://127.0.0.1:5180 — статика без auth (allowlist; без dotfiles)
npm run load-test    # 2500 VU, отчёт в .load-test-report.json
npm run check-deploy # перед продом: падает, если остался example.com
npm run test:security
```

## Правка лендинга (index.html)

У главной страницы **нет отдельного исходника**. Разметка и стили первого экрана
лежат внутри `index.html` (около 190 КБ) одной строкой: это вывод визуального сборщика,
где шаблон закодирован как JSON внутри `<script type="__bundler/template">`.
Править его прямо в файле нельзя – редактировать надо распакованную копию:

```bash
npm run template:extract   # index.html -> .landing-template.html (обычный HTML)
# правите .landing-template.html любым редактором
npm run template:inject    # обратно в index.html, с копией в .index.html.bak
npm run template:verify    # проверка, что цикл ничего не портит; ничего не пишет
```

Обе рабочие копии в git не попадают: источник истины – сам `index.html`, а
закоммиченный распакованный шаблон стал бы второй версией разметки, которая
молча разойдётся с настоящей.

Тонкость, из-за которой самописные варианты этого скрипта ломают страницу:
внутри `<script>` последовательность `</script` закрыла бы элемент раньше времени,
и сборщик экранирует **только её**. Если экранировать каждый `</`, цикл перестаёт
быть обратимым – файл меняется без единой смысловой правки. `template:verify`
именно это и проверяет.

`template:inject` отказывается записывать пустой или вдвое укоротившийся шаблон
(признак обрезанного или чужого файла); осознанное сокращение – через `--force`.

### Вшитые ассеты: вынос в файлы

Сборщик кладёт каждый ассет в `<script type="__bundler/manifest">` как base64, а
в разметке оставляет ссылку на uuid. Для шрифтов это худший вариант доставки:
base64 раздувает данные на треть, всё лежит внутри некешируемой разметки, и
посетитель получает **все** начертания сразу — `unicode-range` умеет отменить
загрузку файла, но data:-URL уже приехал внутри HTML.

```bash
npm run unbundle            # отчёт: что вшито и сколько весит
npm run unbundle -- --apply --js   # вынести шрифты и скрипты в файлы
```

Скрипт идемпотентен: повторный запуск ничего не находит. Имена файлов
**вычисляются** — шрифтам из соседнего `@font-face` (семейство + подмножество по
`unicode-range`), библиотекам из их исходного адреса на CDN. Таблицы uuid
намеренно нет: uuid живут одну сборку, и таблица устарела бы при первой
пересборке лендинга, причём молча. **После пересборки лендинга сборщиком
скрипт надо прогнать заново.**

Сделано 16.08.2026: `index.html` 1027 -> 190 КБ (12 шрифтов и 3 скрипта
переехали в `fonts/`, `js/vendor/`, `js/bundle/`). Библиотеки (React, ReactDOM)
подключаются не тегом, а через карту `__bundler/ext_resources`, поэтому скрипт
дополнительно правит саму карту и одну строку загрузчика — ту, что собирает
`window.__resources`.

## Шрифты

Все страницы используют фирменные шрифты НИУ ВШЭ — **HSE Sans** и **HSE Slab**
(файлы взяты с hse.ru), размещённые локально в `fonts/`. Внешних запросов к
Google Fonts или иным CDN нет — данные посетителей не покидают сайт (152-ФЗ).
Фолбэки: IBM Plex Sans / Source Serif 4 (тоже локальные).

Фолбэки лежат шестью подмножествами каждый (`latin`, `latin-ext`, `cyrillic`,
`cyrillic-ext`, `greek`, `vietnamese`). Греческое и вьетнамское на русском сайте
не скачается никогда — за это отвечает `unicode-range`, и работает он только
потому, что шрифты лежат файлами, а не внутри разметки.

## Безопасность

### Что уже сделано в коде

| Слой | Меры |
|---|---|
| **Админ-сервер** (только локально) | Bind `127.0.0.1`; HTTP Basic Auth; пароль **scrypt-хеш** (не plaintext); CSRF и проверка Origin на всех изменяющих запросах (`/api/update`, `/api/programs`, `/api/schedule`); проверка Origin/Referer; lockout 5 ошибок → 15 мин; throttle 120 req/min; URI ≤ 2048; allowlist файлов + path traversal block; single-flight на обновление каталога; атомарная запись HTML; заголовки `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, `COOP`/`CORP`, CSP, `Cache-Control: no-store` |
| **Публичные страницы** | CSP + Referrer-Policy (meta) на всех лендингах, каталоге, privacy и `index.html` (shell + post-swap inject); email из `data-u`/`data-d`; нет форм ПДн; шрифты локальные |
| **Превью static-server** | Allowlist HTML/assets; deny dotfiles и исходники; bind только loopback (иначе `ALLOW_NON_LOOPBACK=1`); `/api/collect` без CORS |
| **Данные с hse.ru** | URL только `https://*.hse.ru`; HTML-escape всех полей; JSON-LD с экранированием `</` |

`.admin-credentials.json` и `.admin-status.json` в git **не** попадают.

### Реалистичная модель угроз

Это **статический витринный сайт** + **локальный** инструмент обновления. Его нельзя
«взломать как банк»: нет БД пользователей, нет личных кабинетов, нет оплаты на
этом домене. Типичные риски и ответы:

1. **Админку выложили в интернет** — главная ошибка. `admin-server.js` **не**
   деплоить на хостинг; на Pages/S3/Nginx отдавать только HTML/CSS/JS/шрифты.
2. **Подмена файлов на хостинге** — доступ по FTP/SFTP/CI скомпрометирован.
   Лечится: SSH-ключи, 2FA у хостера, read-only deploy, WAF, регулярные бэкапы.
3. **XSS через каталог hse.ru** — снижено: escape + whitelist URL. Держите
   CSP жёстким; не подключайте сторонние скрипты без необходимости.
4. **DDoS / сканеры** — на стороне хостинга (Cloudflare / DDoS-Guard / WAF).
5. **Фишинг / поддельный сайт** — HTTPS + HSTS у хостера, корректный canonical.

### Что усилить при публикации (рекомендации)

- **HTTPS + HSTS** на реальном домене (Let's Encrypt / сертификат хостера).
- **Не публиковать** `admin.html` / `admin-server.js` (или закрыть Basic Auth +
  IP allowlist, если когда-нибудь понадобится удалённый апдейт — лучше CI-job).
- **WAF / anti-bot** у CDN или хостера.
- **CSP** на уровне HTTP-заголовков (надёжнее meta); при возможности убрать
  `'unsafe-inline'` через nonces (нужен шаблонизатор/сервер).
- **Subresource Integrity (SRI)** если появятся CDN-скрипты (сейчас их нет).
- **Регулярно** обновлять Node (для локальной админки) и зависимости хостинга.
- **Пароль админки**: при первом запуске сохраните из терминала; сброс — удалить
  `.admin-credentials.json` и перезапустить `node admin-server.js`.

## Соответствие законодательству

- **152-ФЗ**: без согласия сайт не ставит cookies и не собирает данные; шрифты и
  ресурсы локальные (нет передачи данных третьим лицам и за рубеж). Политика —
  `privacy.html` (ссылки в футерах). Перед публикацией текст политики должен
  утвердить оператор (юридическая служба).
- **Cookies / Яндекс.Метрика**: на страницах ДПО работает баннер согласия
  (`js/cookie-consent.js`): Метрика и её cookies включаются только после
  «Принять», отказ запоминается. **Чтобы включить счётчик, впишите его номер
  в `js/cookie-consent.js` (переменная `METRIKA_ID` в начале файла)** — пока
  он не задан, баннер работает, но счётчик не грузится и cookies не ставятся.
  Вебвизор отключён сознательно (избыточный сбор данных).
- **Доступность** (Приказ Рособрнадзора № 831, ГОСТ Р 52872-2019): на публичных
  страницах есть версия для слабовидящих (кнопка «Версия для слабовидящих» в
  шапке: белый фон, чёрный текст, крупный шрифт, без декора), `lang="ru"` на всех
  страницах, ссылка «Перейти к содержанию» первым фокусируемым элементом,
  ориентиры `header` / `nav` / `main` / `footer`, у всех изображений есть `alt`.
- **Хранение данных аналитики**: события лежат в `.analytics/events/` не дольше
  90 дней (`RETENTION_DAYS` в `lib/analytics-store.js`), IP-адреса и ФИО не
  записываются вообще.
- **Сведения об образовательной организации**: обязательный раздел ведёт на
  официальный `hse.ru/sveden/` (ссылки в футерах) — витрина не подменяет
  официальный сайт образовательной организации.

## SEO

Мета-теги, Open Graph и микроразметка уже проставлены. Перед публикацией на реальном
домене **замените `https://example.com`** в `canonical`/`og:url` страниц, а также в
`robots.txt` и `sitemap.xml` на реальный адрес.

> Примечание: `index.html` рендерится через JavaScript (бандл), поэтому мета-теги
> продублированы во внешнем `<head>` — краулеры и превью в мессенджерах читают
> исходный HTML и JS не выполняют. Там же лежит контентный фолбэк `<noscript>`:
> без скриптов посетитель видит описание центра, телефон, адрес и ссылки, а не
> пустую страницу.

Канонические адреса — короткие: `/catalog` и `/privacy`. Имена файлов
(`/Каталог программ.html`, `/privacy.html`, `/catalog.html`) уводятся на них
редиректом 301. `canonical`, `og:url` и `sitemap.xml` должны указывать именно на
короткие адреса — иначе поисковик получает противоречивые указания.

## Развёртывание

Боевая конфигурация — два контейнера: nginx со статикой и Node-админка.

```bash
docker compose up -d      # сайт: http://localhost:8080, админка: http://localhost:5178/admin.html
docker compose logs admin # здесь печатается пароль при первом запуске
```

**Что здесь важно знать.**

- **Белый список в `docker/nginx.conf` трогать осторожно.** В контейнер nginx
  монтируется весь каталог проекта — иначе админка не смогла бы переписывать
  «Каталог программ.html» на месте. Значит, под корнем веб-сервера физически
  лежат `admin-server.js`, `Dockerfile`, `.git/` и `.admin-credentials.json`
  с логином и хешем пароля админки. Наружу их не пускает единственное правило —
  `location ~ "^/(?!...)"` в конце конфига. Если сайт разворачивают **не** этим
  compose-файлом (свой nginx, Apache, любой другой веб-сервер), это правило
  нужно воспроизвести, иначе учётные данные будут доступны по HTTP кому угодно.
  Правило закреплено проверкой в `tests/security_test.py` и живым запросом
  18 адресов в CI.
- **Порт админки публикуется только на `127.0.0.1` хоста.** Снаружи она
  недоступна; чтобы зайти с другой машины, нужен SSH-туннель, а не проброс порта.
- **Права на каталог.** Контейнер админки работает под uid 1000, а каталог
  сайта монтируется с хоста и перекрывает права из образа. На сервере:
  `chown -R 1000:1000 /srv/dpo`, иначе кнопка «Обновить» вернёт ошибку записи.
- **Время — московское, независимо от зоны сервера.** hse.ru отдаёт старт
  программы меткой московской полуночи, а контейнеры живут в UTC; расписание
  автообновления, даты в карточках и отчёты аналитики принудительно считаются по
  Москве (`lib/moscow-time.js`). Менять `TZ` контейнера не нужно и бесполезно.
- `admin-server.js` на статическом хостинге (GitHub Pages, S3) не запустится —
  там будет только вёрстка, без обновления каталога и аналитики.
- Имена файлов с пробелами и кириллицей открываются корректно (браузер кодирует
  URL), но в ссылках и карте сайта используйте короткие адреса.
