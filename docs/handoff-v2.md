# Спека для реализации: токены, компоненты, состояния

Собрана 18 августа 2026 г. Все числа – замеры на рабочем дереве `main`, а не
оценки. Где написано «сейчас», это факт, а не впечатление.

Документ адресован тому, кто будет править код. Он не про облик, он про то,
какие значения считать источником правды и где именно их менять.

## 0. Как устроен этот проект

Без этого раздела спека приведёт к потерянной работе.

**Зависимостей нет.** `package.json` пуст на `dependencies` и `devDependencies`,
`node_modules` отсутствует. Библиотеки не подключать. Сборщика нет, есть свои
скрипты в `scripts/`.

**HTML генерируется.** Правка вывода бессмысленна: первая же пересборка её
затрёт. Карта источников:

| Что правим | Где на самом деле лежит |
| --- | --- |
| Разметка и стили лендинга | шаблон внутри `index.html`, достаётся `node scripts/landing-template.js extract` |
| Динамические блоки лендинга | регионы-маркеры в `scripts/build-landing.js` |
| Карточки каталога, микроразметка | `update-catalog.js` |
| 26 страниц программ и их CSS | `scripts/build-program-pages.js` (CSS – в шаблонной строке в конце файла) |
| Форма заявки, её стили и тексты | `js/application-form.js` (CSS собирается массивом строк) |
| Домен во всех местах | `scripts/set-domain.js` |

**Шаблон лендинга – JSON-строка внутри `<script type="__bundler/template">`.**
Цикл правки: `extract` → правка обычного HTML → `inject` → `verify`. Команда
`verify` обязана сказать «цикл обратим» после каждой правки.

**Регионы-маркеры.** Шесть блоков лендинга собираются автоматически по парам
комментариев (`dpo:teachers:start` / `:end` и другие). Внутрь регионов руками не
писать. Два региона живут в статической части `index.html`, вне шаблона:
`dpo:noscript-programs` и `dpo:slogan` – они пишутся ПОСЛЕ упаковки шаблона,
потому что упаковка переписывает файл целиком.

**Проверка после каждой правки:**

```
npm test                                    # 134 юнит-теста
node scripts/landing-template.js verify     # обратимость цикла
tests/run.sh                                # Playwright: смоук, девизы, блок программ, безопасность
```

### 1.2 Цвет: целевой набор

Роли, а не оттенки. Значения существующие, новых цветов не вводится.

```css
:root {
  /* Акцент. Единственный. */
  --accent:            #1658DA;   /* синий НИУ ВШЭ */
  --accent-deep:       #1145AA;   /* нажатие, тёмный фон */

  /* Второй акцент – только на синем фоне, см. 1.4 */
  --gold:              #F0B86E;
  --gold-light:        #FFD982;

  /* Бумага */
  --paper:             #FBF9F5;   /* основной холст */
  --paper-sunk:        #F2ECE1;   /* утопленная секция */
  --surface:           #FFFFFF;   /* карточка, поле ввода */

  /* Текст. Одно семейство – тёплое. */
  --ink:               #211E1B;   /* основной */
  --ink-secondary:     #48423A;   /* вторичный */
  --ink-muted:         #6B6459;   /* подписи, мета, даты */

  /* Линии */
  --hairline:          rgba(33, 30, 27, 0.10);
  --border-field:      rgba(33, 30, 27, 0.42);  /* см. 1.5 – контраст */

  /* Радиусы */
  --radius-pill:       999px;
  --radius-lg:         24px;
  --radius-md:         16px;
  --radius-sm:         8px;

  /* Ритм */
  --space-chapter:     96px;
  --space-section:     64px;
  --space-block:       40px;
  --gutter:            clamp(20px, 5vw, 56px);
  --container:         1440px;

  /* Движение */
  --ease:              cubic-bezier(0.16, 1, 0.3, 1);
  --dur-fast:          160ms;
  --dur:               240ms;
}
```

### 1.3 Что уходит и почему

| Значение | Вхождений | Причина |
| --- | --- | --- |
| `#55503E` | 88 | **Оливковый** серый среди тёплых. Два семейства нейтралей в одном тексте. Заменить на `--ink-secondary` |
| `#787165` | 1 | Четвёртый серый на ту же роль. Заменить на `--ink-muted` |
| `rgba(33,30,27, .07 / .12 / .14 / .22 / .25)` | 47 суммарно | Шесть альф одной и той же краски. Свести к `--hairline`, кроме границы поля |
| `border-radius: 15px` | 6 | Дрейф от `16px`. Глаз разницы не видит |
| `border-radius: 12px` | 1 | Единичное значение вне шкалы |
| `border-radius: 50%` | 7 | Дублирует `999px` |

### 1.4 Золото: требует решения

Замер: `#F0B86E` встречается фоном **один раз**, `#FFD982` текстом **четыре
раза**. Заявленный второй акцент фактически отсутствует.

Два пути, выбор заказчика:

1. **Дать работу** – надзаголовки на синем, акцент в блоке документов, цифры
   факультета. Тогда золото становится настоящим вторым акцентом.
2. **Убрать из токенов** – признать, что акцент один.

Если путь 1: контраст золота на синем имеет **нулевой запас** (замер в
`docs/contrast-audit.md`). Использовать только `--gold-light` `#FFD982` и
перемерять на каждом фоне.

### 1.5 Контраст: две обязательные правки

Не вкусовщина, измеренные нарушения WCAG 1.4.11 и 1.4.3.

| Что | Сейчас | Норма | Правка |
| --- | --- | --- | --- |
| Граница поля ввода | **1,38:1** и **1,22:1** | 3:1 | `--border-field: rgba(33,30,27,0.42)`, пересчитать точно |
| Плейсхолдер | **3,38:1** (`#6B6459` при `opacity:.75` = `#908b83`) | 4,5:1 | Убрать `opacity: .75`. Чистый `#6B6459` на белом даёт 5,85:1 |

## 2. Типографика

### 2.1 Критическое: HSE Slab не имеет начертания 600

`HSESlab-Regular.woff2`: `usWeightClass = 400`, таблицы `fvar` нет. В
`@font-face` объявлен диапазон `font-weight: 400 600`, поэтому запрос 600
попадает внутрь диапазона и **браузер не синтезирует жирный**.

Замер ширины строки при кегле 100px: веса 300 / 400 / 500 / 600 дают ровно
**1258,41px**. У HSE Sans вес 600 настоящий (1186,41 против 1169,50).

На лендинге 128 элементов набраны слэбом, большинство с весом 600. **Все
рисуются весом 400.** Иерархия заголовков держится только на кегле.

**Требует решения заказчика.** Три пути:

1. Запросить у ВШЭ `HSESlab-SemiBold` – система заработает как задумана;
2. Сузить диапазон в `@font-face` до `400` – браузер честно синтезирует жирный;
3. Признать один вес и убрать 600 из токенов слэба.

До решения шкалу весов не фиксировать.

### 2.2 Шкала кеглей

Сейчас **20 уникальных значений**, восемь из них (12,5 / 13 / 13,5 / 14 / 14,5 /
15 / 15,5 / 16) умещаются в 3,5 пикселя. Это дрейф, а не шкала.

| Роль | Сейчас | Целевое | Токен |
| --- | --- | --- | --- |
| Подпись, мета, чип | 12,5 / 13 / 13,5 | **13** | `--fs-caption` |
| Основной текст | 14 / 14,5 / 15 | **15** | `--fs-body` |
| Крупный текст, лид карточки | 15,5 / 16 | **16** | `--fs-body-lg` |
| Заголовок карточки | 19 | 19 | `--fs-h3` |
| Заголовок блока | 21 / 22 | **21** | `--fs-h2-sm` |
| Заголовок секции | 28 / 30 | оставить `clamp` | `--fs-h2` |

Основной кегль растёт с 14,5 до 15: 14,5 – кегль 118 элементов, а аудитория 35+
читает с телефона. Шаг ничего не ломает.

### 2.3 Семейство: одно базовое правило

У `body` лендинга **нет `font-family` ни в одном из четырёх блоков `<style>`**.
Остальные 343 элемента спасает то, что каждый задаёт семейство сам. Два не
задают и выпадают:

- `.dpo-mobile-cta a` – **Times New Roman**, 14px, синтетический жирный
- `.ci-close` – **Arial**, 17px

Правка одна:

```css
body { font-family: 'HSE Sans', 'IBM Plex Sans', sans-serif; }
```

После неё семейство можно снимать с сотен отдельных элементов.

Отдельные дефекты:

- `max 720px` живёт внутри мёртвого семейства `.dpo-rank` (75 строк CSS, ноль
  элементов на странице) – удалить вместе с ним;
- `.dpo-split` объявлен дважды, на `max 860` и `max 760`. Работает 860, а
  `DESIGN.md:394` утверждает 760. Оставить один, документ привести к факту.

### Целевая сетка

```
520px   – телефон / крупный телефон
760px   – планшет
1080px  – десктоп
1440px  – ширина контейнера (не брейкпоинт)
```

Правило: секции остаются во всю ширину, чтобы заливки и кадр героя не потеряли
размах; содержимое внутри получает `max-width: var(--container); margin: 0 auto`.

Сейчас контейнера нет **ни на одной поверхности**: при 2560px абзац в карточке
растягивается до 743px при кегле 14,5 – около 106 знаков при норме 60–75.

## 6. Движение

`MOTION_INTENSITY: 4`. Конкретно:

| Элемент | Событие | Что происходит | Длительность |
| --- | --- | --- | --- |
| Секция | Появление в окне | `opacity` 0→1, `translateY` 16px→0 | `--dur`, `--ease` |
| Карточка | Наведение | `translateY(-2px)` + тонированная тень | `--dur-fast` |
| Кнопка | Нажатие | `translateY(1px)` | 80ms |
| Диалог формы | Открытие | `opacity` + `scale(.98)`→1 | `--dur` |

Постоянной микроанимации нет. Человек приходит один-два раза и принимает
решение о покупке – пульсирующие элементы мешают.

`@media (prefers-reduced-motion: reduce)` гасит всё до статики. Анимировать
только `transform` и `opacity`.

## 7. Доступность: что чинить обязательно

Замеры вживую, Chromium, пять поверхностей.

| Нарушение | Критерий | Замер | Правка |
| --- | --- | --- | --- |
| В режиме для слабовидящих исчезает индикатор фокуса | 2.4.7 | лендинг **5 из 6** элементов, `ratings.html` **5 из 6** | `html.vi-mode :focus-visible { outline: 3px solid #000 !important; outline-offset: 2px }`. Правило уже работает в каталоге, скопировать дословно |
| В форме сфокусированное поле неотличимо от обычного в vi-mode | 2.4.7 | `outline: нет`, `box-shadow: нет`, `border: rgb(0,0,0)` – как у несфокусированного | То же правило в CSS-массив `js/application-form.js` |
| Скип-ссылка не переносит фокус | 2.4.1, 2.4.3 | на лендинге после Enter фокус **остаётся на ссылке** | После прокрутки: `target.tabIndex = -1; target.focus({preventScroll:true})` в `js/smooth-ui.js` |
| Мишени меньше 44×44 | 2.5.5 | лендинг 84, каталог 35, программа 8 | `min-height: 44px` кнопкам-действиям |
| `role="listitem"` на `<a href>` | 4.1.2 | 5 тайлов «Топ-5» не попадают в список ссылок | Снять `role` либо обернуть в `<li>` |
| Списки теряют семантику в Safari | 1.3.1 | 13 из 14 `<ul>` с `list-style: none` | Проставить `role="list"` |
| Латиница без `lang` | 3.1.2 | 89 вхождений, `lang="ru"` только на `<html>` ×32 | `<span lang="en">` в генераторах |

Проходит и трогать не надо: подписи полей (21 из 21), зум 200 % без
горизонтальной прокрутки, ориентиры, один `h1`, ноль пропусков уровней
заголовков, `role="dialog"` с `aria-modal` и фокусом внутри.
