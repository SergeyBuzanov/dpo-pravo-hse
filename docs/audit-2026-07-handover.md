## Прочитать первым

Четыре вещи, из-за которых можно потерять время, если про них не знать.

**Ветки `main` и `dev` разошлись, и это не устранено.** Работа велась от `main`, а
параллельно развивался `dev`: там уже лежали статическая главная, Docker и CI. Ветку
перенесли поверх `dev`, конфликты развели вручную. Сейчас `dev` впереди на 41 коммит, а в
`main` висит один старый коммит, содержимое которого в `dev` уже есть. Что делать с
`main` - решение владельца репозитория.

**Файл каталога переименован.** `Каталог программ.html` стал `catalog.html`. Обновлены все
ссылки, маршрут в админке, `CATALOG_FILE` в апдейтере, правила nginx, тесты и README. Если
есть локальные ветки, трогающие этот файл, при слиянии он покажется удаленным и созданным
заново.

**Обновление каталога скриптом теперь требует заголовка.** `POST /api/update` без признаков
происхождения запроса отдает 403 - это защита от CSRF. Кнопка в админке работает как
раньше, она шлет `X-Requested-With: dpo-admin`. Если обновление дергается из `curl` или
cron, нужен тот же заголовок.

**Контейнер админки больше не работает от root.** В `Dockerfile` добавлен `USER node`.
Примонтированный с хоста каталог сайта перекрывает права из образа, поэтому на сервере
понадобится `chown -R 1000:1000 /srv/dpo`. Иначе кнопка «Обновить» вернет ошибку записи -
она видна в статусе админки, молча ничего не сломается.

## Откуда все это взялось

24 июля был проведен аудит сайта - 31 находка. По ним написан план на 20 задач с готовым
кодом и пошаговыми проверками. Часть задач к тому моменту была уже закрыта на `dev`:
переписывание главной статикой, Docker с CI, защита админки от CSRF и блокировка
параллельного обновления. Эти задачи из объема сняты, остальные выполнены.

Работа шла по одному правилу: **сначала падающая проверка, потом правка**. Там, где
проверка оказывалась зеленой сразу (баг уже был исправлен), она проверялась мутацией - в
код возвращался исходный дефект и подтверждалось, что тест на него падает. Это отсекает
проверки, которые ничего не проверяют.

## Каталог и его обновление

Данные приходят с hse.ru и попадают в разметку и в микроразметку для поисковиков. Здесь
были самые заметные ошибки.

**Программа без цены больше не объявляется бесплатной** (`ea97dfc`). Было
`if (!price) return 'Бесплатно'` - отсутствующая цена и явный ноль обрабатывались
одинаково. Платная программа, у которой hse.ru не отдал цену, выводилась как бесплатная.
Теперь «Бесплатно» только при явном нуле, иначе «Цена по запросу».

**Дата старта в микроразметке уезжала на сутки назад** (`e21d795`, `0aeebd2`).
`toISOString()` переводит время в UTC и для ночных часов по Москве отдавал предыдущие
сутки: на карточке одна дата, в JSON-LD для поисковика - другая. Добавлена `isoDate`,
собирающая дату из локальных компонент. Тот же баг позже нашелся в автообновлении
`lastmod` карты сайта и исправлен там же.

**Одна битая дата больше не роняет обновление целиком** (`b5a4d25`). `Intl` бросает
исключение на невалидной дате - одна испорченная запись в выдаче hse.ru прекращала
обновление всего каталога. Теперь такая программа остается в выдаче без даты.

**Разбор данных не ломается на названиях с запятой и двоеточием** (`254039a`, `842b661`,
`4911253`). hse.ru отдает данные не как JSON, а как JS-литерал. Он приводился к JSON тремя
регулярками по сырому тексту, и каждая портила такой же текст внутри строковых значений:
название вида «Комплаенс, compliance: практика» разбиралось как объявление ключа. Все три
операции сведены в один посимвольный проход, который вне строк ничего не пропускает, а
внутри строк не трогает ничего. Линейность подтверждена замером: 8000/16000/32000
вхождений - 17/32/61 мс.

**Обрыв записи не оставляет обрезанный каталог** (`cc249f6`). Файл переписывался на месте.
Каталог при этом еще и шаблон для следующего обновления: потеряв маркеры `CATALOG:*`,
апдейтер больше не запустился бы. Теперь запись идет во временный файл рядом с последующим
переименованием.

**Битая ссылка программы больше не подменяется общим каталогом** (`36ead72`). `safeHseUrl`
при неразобранном адресе возвращал ссылку на общий список программ: карточка выглядела
обычной, а вела не туда, и пользователь этого не замечал. Теперь такая программа
пропускается с предупреждением в лог, а если годных ссылок не осталось вовсе - обновление
отменяется, а не переписывает каталог пустым списком.

**Таймаут на запрос к hse.ru** (`56182ba`). У нативного `fetch` нет таймаута по умолчанию:
зависшее соединение вешало обновление навсегда. Сейчас 25 секунд с понятным сообщением об
ошибке. **На заметку:** в `dev` было 30 секунд, обе стороны чинили это независимо; осталась
версия с обработкой сетевых ошибок и тестом.

**Апостроф экранируется** (`36ead72`). `escapeHtml` не трогал апостроф. Это было безопасно
ровно потому, что все атрибуты в шаблонах записаны в двойных кавычках - договоренность,
которую ломает первая же правка. Апострофы в названиях программ встречаются.

Закрыт и старый хвост: закоммиченный каталог был снят до всех этих правок и содержал в
JSON-LD даты на сутки раньше, чем на карточках. Пересобран апдейтером - 20 программ, даты
совпадают.

## Доступность и верстка каталога

**Фильтры стали понятны скринридерам** (`525c893`). Чипы были `<button>` без
`aria-pressed`, группы - без роли и подписи, а сообщение «программ не найдено» появлялось
молча. Человек со скринридером не узнавал ни какой фильтр активен, ни что выдача опустела.
Добавлены `aria-pressed` (в генератор, в разметку и в обработчик клика - иначе состояние
разъезжается после первого переключения), `role="group"` с подписью и `aria-live` на пустое
состояние.

**Панель фильтров не уезжает под шапку** (`ac21523`). Отступ липкой панели был зашит числом
(61px). В режиме для слабовидящих страница масштабируется, шапка становится выше и
перекрывала фильтры на 17 пикселей - ровно у тех, для кого этот режим сделан. Высота шапки
теперь пересчитывается: при загрузке, при изменении размера окна, после готовности шрифтов
и при переключении режима.

**Учтена системная настройка «меньше движения»** (`ac21523`). На главной
`prefers-reduced-motion` уже был, в каталоге - нет. Плавная прокрутка и анимации у части
людей вызывают головокружение.

**Контраст под сторожем** (`5e857ba`). Аудит нашел вспомогательный текст с контрастом
4,31:1 на карточке и 3,92:1 в футере при норме 4,5:1. Цвет к тому моменту уже был исправлен
на `#666666`, поэтому добавлена только проверка: контраст считается по формуле WCAG на
фактическом фоне. Ее честность подтверждена мутацией - возврат старого цвета роняет обе
проверки ровно с цифрами из аудита.

## Админка: надежность и безопасность

**Дыра в защите от CSRF** (`c4f3028`). Проверка выглядела как
`sameSite && sameSite !== 'same-origin'`: если браузер не прислал `Sec-Fetch-Site`, запрос
проходил, а `Origin` не проверялся вовсе. То есть защита работала ровно для тех браузеров,
которые и так защищены. Дыра была показана падающим тестом буквально: `POST /api/update`
вообще без единого заголовка запустил реальное обновление и переписал файлы.

Решение вынесено в `isCrossSiteRequest` и стало fail-closed: свой заголовок - принять; есть
`Sec-Fetch-Site` - решать по нему; есть `Origin` - сверить с `Host`; нет ничего - отказ.

**Необработанное исключение больше не оставляет админку в подвешенном состоянии**
(`3ad269f`). Обработчик логировал ошибку и оставлял процесс жить. Состояние процесса после
такого исключения неопределенное, а незакрытая блокировка обновления навсегда оставила бы
админку в режиме «обновление уже идет» - то есть кнопка перестала бы работать до
перезапуска, и молча. Теперь логируем и выходим с кодом 1.

**Сравнение паролей перестало выдавать длину** (`3ad269f`). `safeEqual` был объявлен
сравнением постоянного времени, но выходил раньше при разной длине строк - длину пароля
можно было нащупать по времени ответа. Сравниваются хеши фиксированной длины.

**`require` больше не поднимает сервер** (`3ad269f`). `server.listen` выполнялся при любом
импорте файла: занимал порт и заводил таймер автообновления. Из-за этого админку нельзя
было ни протестировать, ни переиспользовать. Спрятано под `require.main === module`.

**Проверено живьем и менять не нужно:** обход каталога не проходит - четыре вектора
(`../`, `%2e%2e%2f`, попытка достать файл с учетными данными) дали 404; брутфорс закрыт
(5 попыток - блокировка на 15 минут, задержка ответа 700 мс, троттлинг 120 запросов в
минуту); пароль генерируется случайным и в истории git никогда не был; оба порта
публикуются только на `127.0.0.1`; `/admin.html` и `/archive/` отдают 404.

## Раздача, адреса и заголовки

**Каталог переименован в `catalog.html`** (`d2f8f1e`). Страница отдавалась по адресу
`/%D0%9A%D0%B0%D1%82%D0%B0%D0%BB%D0%BE%D0%B3%20...` - такую ссылку не продиктовать и не
поставить в рекламу. В nginx редирект со старого кириллического пути заменен на
`/catalog.html` → 301 → `/catalog`: сайт еще не опубликован, редиректить не с чего, а
дублирующий адрес с расширением теперь сводится к каноническому, как уже сделано для
privacy.

**Сверка адресов между четырьмя источниками** (`8d477ca`). Появилась проверка, которая
сверяет sitemap, `canonical` и `og:url` страниц, ЧПУ-правила nginx и `robots.txt`.
Тонкость: адреса вида `/catalog` - не файлы, их отдает nginx по `try_files`, поэтому
существование адреса решается по конфигу, а не по наличию файла. Когда появится домен, эта
же проверка поймает страницу, где его забыли заменить.

Она сразу нашла пробел: у `privacy.html` не было ни одного тега Open Graph, кроме картинки
- ссылка на политику в мессенджерах выглядела бы голой. Добавлена и отдельная проверка на
`og:image`: это единственная ссылка на файл в шапке, которую не видит ни браузер, ни
проверка битых ресурсов, - ее грузит соцсеть.

**Заголовки хостинга описаны, конфиг усилен** (`e3154f8`). Появился
[`docs/hosting-headers.md`](hosting-headers.md): почему `frame-ancestors` в `<meta>` не
работает, минимум заголовков, готовые куски конфигов nginx и Apache, проверка `curl` после
публикации. Отдельно отмечена грабля: `add_header` внутри `location` отменяет
унаследованные с уровня `server` заголовки, а не дополняет их. В нашем конфиге
`X-Frame-Options` поднят с `SAMEORIGIN` до `DENY` плюс `frame-ancestors 'none'` - iframe на
сайте не используется нигде.

**`robots.txt` больше не рекламирует путь админки** (`141d819`). Строка
`Disallow: /admin.html` убрана. В самой админке стоит `noindex`, а `Disallow` помешал бы
роботу его увидеть - это классическая ловушка, при которой адрес попадает в выдачу без
содержимого.

## Тесты и CI

Было 24 проверки смоука и ни одного юнит-теста. Стало 77 и 58.

**Юнит-тесты не запускались нигде - это нашло ревью** (`bc2c707`). К моменту ревью в
репозитории было 50 юнит-тестов, и ни CI, ни `tests/run.sh` их не гоняли. То есть все, что
этими тестами гарантируется, держалось на том, что кто-то наберет `node --test` руками.
Добавлен отдельный job.

**Конфиг nginx тоже не проверялся нигде** (`bc2c707`). Он не входит в образ админки, а
монтируется в контейнер веб-сервера при запуске - ошибка в нем обнаружилась бы только на
живом сервере. Добавлен шаг `nginx -t` на смонтированном конфиге; в первом же прогоне
отработал.

**Права токена и пин actions** (`c4f3028`). У workflow не было блока `permissions` -
действовало умолчание репозитория, нередко `contents: write`. Теперь `contents: read`.
Actions запинены по SHA: тег можно переписать на стороне автора, и CI выполнит чужой код с
доступом к репозиторию.

**Что именно покрыто.** Смоук: главная, каталог, политика, клуб выпускников - верстка,
доступность, контраст, отсутствие ошибок в консоли, отсутствие битых ресурсов, ноль внешних
сетевых запросов (152-ФЗ), внутренние ссылки ведут на существующие страницы, сверка
адресов. Юниты: разбор данных hse.ru, цены, даты, микроразметка, таймаут, атомарная запись,
карта сайта, экранирование, отбраковка негодных ссылок, админка (сравнение паролей,
отсутствие побочного эффекта при `require`, остановка процесса, решение о происхождении
запроса).

## Требует действий

Кодом это не закрывается. Первые три пункта блокируют публикацию независимо от готовности
кода.

### Сверить с факультетом: непроверяемые данные о людях и цифры

Выглядят как заглушки из макета, но будут опубликованы как факты. На странице клуба
выпускников: имя координатора и прямой добавочный номер (строки 502-505), «25 лет истории»
и «4300+ выпускников в базе клуба» (364-365), канал `t.me/pravo_alumni` (488). На главной:
«топ-150 в рейтингах THE и QS по праву» и два блока «50+» (381-383). Публикация имени и
прямого номера конкретного сотрудника без подтверждения - отдельный репутационный риск.

### Юридическая служба: политика ПДн не утверждена

В самом файле стоит примечание, что документ типовой и требует утверждения юрслужбой НИУ
ВШЭ. Плюс три конкретных вопроса: оператором указан адрес Большой Трехсвятительский
переулок, 3 - это адрес корпуса факультета, а не юридический адрес университета; в
документе нет ни сроков обработки и хранения, ни срока ответа на обращение; формулировку
про «обезличенную статистику» Яндекс.Метрики Роскомнадзор трактует иначе - IP и cookie
считаются персональными данными.

### Согласовать: права на шрифты и бренд

В репозитории лежат и раздаются фирменные шрифты НИУ ВШЭ, на всех страницах стоит
«© НИУ ВШЭ». Если проект не официальный ресурс университета, использование нужно
согласовать.

### Решение: домен не выбран

Плейсхолдер `example.com` остался в шести файлах: `index.html`, `catalog.html`,
`privacy.html`, `sitemap.xml`, `robots.txt` и странице клуба. Замена делается разом,
проверка сверки адресов тут же покажет, если где-то пропущено. Canonical, указывающий на
чужой домен, - это прямая команда поисковику не индексировать страницу.

### При развертывании

- `chown -R 1000:1000 /srv/dpo` - контейнер админки больше не root.
- Раскомментировать HSTS в `docker/nginx.conf`, но только после того, как TLS реально
  работает: браузер запомнит https для домена, и при неготовом сертификате сайт станет
  недоступен.
- Вписать номер счетчика в `js/cookie-consent.js` - сейчас `METRIKA_ID = null`, баннер
  согласия работает, а счетчик не грузится вообще.
- Раскомментировать deploy-job в CI и завести секреты.
- Если хостинг будет не наш nginx - воспроизвести заголовки из
  [`docs/hosting-headers.md`](hosting-headers.md).

## Сознательно не делалось

**`script-src 'unsafe-inline'` в CSP публичных страниц.** От XSS эта политика не защищает.
Известного вектора нет: данные с hse.ru экранируются, на это есть тесты. Убирается выносом
инлайновых скриптов в файлы или хешами `sha256-` на всех страницах - отдельная работа на
несколько часов.

**Монтирование всего репозитория в контейнер админки.** `compose` отдает `.:/app` на
запись, включая `.git` и `.github/workflows`. Стоит сузить до файлов, которые апдейтер
реально переписывает. Проверить без docker на машине разработки нельзя - только через CI.

**Страница клуба выпускников.** По решению владельца оставлена как есть и из объема плана
исключена - правились только ссылки и заголовки, затронутые общими изменениями.

## Как проверить у себя

```bash
git checkout dev && git pull

# юнит-тесты (58) - зависимостей не требуют, нужен только Node 18+
node --test tests/unit/*.test.js

# смоук-тест (77) - сам поднимет окружение через uv и поставит Chromium
bash tests/run.sh

# посмотреть сайт локально
python -m http.server 5173 --bind 127.0.0.1

# админка
node admin-server.js   # затем http://127.0.0.1:5178/admin.html
```

### Грабли платформы, на которые уже наступали

- **PowerShell пишет BOM** даже с `-Encoding utf8`. В проекте требуется UTF-8 без BOM:
  создавайте файлы из Git Bash или через `[IO.File]::WriteAllText` с `UTF8Encoding($false)`.
  Один BOM в файле тестов уже ловили на ревью.
- **`node --test tests/unit/` без маски не работает** на Windows - раннер пытается
  выполнить каталог как модуль. Всегда `tests/unit/*.test.js`.
- **Без `PYTHONIOENCODING=utf-8`** смоук падает на символе «≥» в консоли с cp1251. Строка
  экспорта уже вписана в `tests/run.sh`.
- **`git checkout -- file` уносит и ваши правки** в этом файле, если они не закоммичены.
  Так уже была потеряна одна правка после отката тестового прогона генератора - нашлось
  только на ревью.
