Продолжение [аудита цветовой системы](color-system-audit.md): проверяется палитра,
которая остаётся после введения 7 токенов.

Цель – AA: **4.5:1** для обычного текста, **3:1** для крупного (≥24px, либо
≥18.66px при начертании 600+) и для нетекстовых элементов (1.4.11).

## 1. Ошибки

### 🔴 1.1. Каталог программ: мета-плашка в герое – 3.98:1

`Каталог программ.html:119`

```css
.hero .meta{ font-size: 13px; color: rgba(255,255,255,0.88);
             background: rgba(255,255,255,0.14); }
```

Плашка лежит на синем герое `var(--blue)` = `#1658DA`. Полупрозрачный белый фон
плашки осветляет подложку до `#376FDF`, и текст `rgba(255,255,255,0.88)` на ней
даёт **3.98:1** при требуемых 4.5:1. Кегль 13px – крупным текстом не считается.

Разбор слоёв:

| Слой | Значение | Результат |
|---|---|---|
| Секция | `#1658DA` | – |
| Фон плашки | `rgba(255,255,255,0.14)` | подложка становится `#376FDF` |
| Текст | `rgba(255,255,255,0.88)` | эффективный `#E7EEFB` |
| | | **3.98:1** ❌ |

Три способа закрыть, в порядке предпочтения:

1. Текст сделать сплошным `#fff` → **4.65:1** ✅. Минимальная правка, вид почти
   не меняется.
2. Убрать подсветку фона плашки (`background: rgba(255,255,255,0.14)` → `none`
   или граница вместо заливки) → текст ляжет прямо на `#1658DA` и даст
   **5.09:1** ✅.

Поднимать альфу текста бесполезно: подсветка фона осветляется вместе с ним, и
даже `0.96` даёт лишь **4.42:1**. Ослаблять подсветку тоже мало – при `0.10`
получается **4.28:1**. Работают только два варианта выше.

Вложенный `.hero .meta b { color: #fff }` (строка 120) уже сплошной белый и
даёт 4.65:1 – то есть жирная часть плашки проходит, а обычная нет.

### 🟡 1.2. Границы полей ввода – 1.69:1

`rgba(33,30,27,0.25)` на белом поле = **1.69:1** при требуемых 3:1 по 1.4.11.

Само по себе это не нарушение: критерий требует 3:1 только когда граница –
единственное, что обозначает поле. Здесь именно этот случай: поле залито `#fff`
на фоне страницы `#FBF9F5`, разница между ними **1.06:1**, то есть край поля
виден только по рамке.

Затрагивает: `search-wrap input` и `sort-select` в каталоге, поля редактора в
админке, поля формы заявки в `js/application-form.js`.

Чтобы закрыть, альфу рамки надо поднять до `0.50` – это даёт **3.25:1**.
Промежуточные значения не спасают: `0.45` даёт лишь 2.82:1.

Границы карточек (`rgba(33,30,27,0.1)`, 1.22:1) под критерий **не подпадают**:
карточка читается как объект по своей заливке и тени, рамка декоративна.
Их трогать не нужно.

### 🟡 1.3. Админка: индикатор несохранённой правки – 2.08:1

`admin.html:434` – `.dirty-dot`, кружок 8×8px, `background: #E6A23C` на `--bg`
`#FBF9F5` = **2.08:1** при требуемых 3:1.

Точка несёт смысл («есть несохранённая правка») и является единственным его
носителем, то есть попадает и под 1.4.11, и под 1.4.1 (информация не должна
передаваться одним лишь цветом).

Закрыть: затемнить до `#B37400` (**3.69:1**) и добавить текстовую подпись или
`title`/`aria-label` рядом с точкой. Промежуточный `#C98A20` не проходит – 2.80:1.

Поверхность внутренняя, пользователей сайта не касается – отсюда средний
приоритет, а не высокий.

### 🟢 1.4. Точки-разделители – 2.64:1

`#A39A8C` на `#FBF9F5` = 2.64:1. Это `content: '·'` в
`.dpo-format-facts span + span::before` – чисто декоративный разделитель между
фактами, смысла не несёт, факты разделены и пробелами. Под 1.4.3 не подпадает.

Оставить можно. Если хочется чистоты – `#787165` даёт 4.59:1 и визуально почти
не отличается.

## 2. Нулевой запас: золото на синей секции

`#FFD982` на `#1658DA` = **4.5025:1** при пороге 4.5. Проходит с запасом
**0.0025**, то есть фактически на самой границе.

Место: секция «Авторы и преподаватели» (`.dpo-on-dark`, строка 2246
раскодированного шаблона), надзаголовок 13px/600 и заголовок
`clamp(22px, 2.8vw, 38px)`. Заголовок – крупный текст, ему хватает и 3:1.
Проблема только у надзаголовка 13px.

Риск конкретный, а не теоретический. Фон секции задан как `background: {{ accent }}`,
а `accent` берётся из `this.props.accentColor ?? '#1658DA'` – то есть синий
перекрашиваем снаружи. Что будет с золотом при других значениях:

| Акцент | `#FFD982` на нём | |
|---|---|---|
| `#1658DA` (текущий) | 4.50:1 | ✅ впритык |
| `#1145AA` | 6.31:1 | ✅ |
| `#0F3FA0` | 6.92:1 | ✅ |
| `#2B6FE0` (светлее на шаг) | 3.48:1 | ❌ |
| `#4B8BFF` | 2.41:1 | ❌ |

Достаточно осветлить акцент на один шаг – и надзаголовок падает ниже AA,
причём молча.

Что сделать:

1. Дать надзаголовку в этой секции сплошной `#fff` (**6.10:1**) либо
   осветлить золото до `#FFE09A` (**4.76:1**). Первое проще. Затемнять золото
   нельзя – оно светлее фона, и от затемнения контраст падает: `#F5C95F` даёт
   уже 3.89:1.
2. Если перекрашиваемость через `accentColor` действительно нужна – зафиксировать
   в `DESIGN.md` границу: акцент не светлее `#1658DA`, иначе золото и белый на
   нём перестают проходить.

## 4. Обложки плиток программ

Белый ранг `#fff` 30px/600 (крупный текст, порог 3:1) на градиенте
`rgba(11,42,105,0.55) → rgba(6,23,57,0.72)` поверх снимка программы.

Ранг стоит `left: 16px; bottom: 10px` на обложке высотой 110px, то есть в нижней,
самой тёмной части градиента. Прогнал все **25** снимков в `images/programs/`,
измеряя только прямоугольник под цифрой:

| | Результат |
|---|---|
| Худший снимок | `816497962.jpg` – **5.56:1** ✅ |
| Лучший | `814248062.jpg` – 17.21:1 |
| Ниже 3:1 | нет |
| Ниже 4.5:1 | нет |

Проходит с запасом, причём даже по строгому порогу 4.5:1, хотя ранг – крупный
текст и ему достаточно 3:1.

Оговорка: измерялась область под цифрой. Если на обложку когда-нибудь положат
текст выше по кадру, там светлее – в верхней трети обложек контраст падает
до 3.5:1.

## 7. Приоритеты

1. **Мета-плашка в герое каталога** – единственное место, где обычный текст не
   добирает до AA. Правка в одну строку: `rgba(255,255,255,0.88)` → `#fff`.
2. **Надзаголовок золотом на синей секции** – формально проходит, но запас
   0.0025 и фон перекрашиваем снаружи. Перевести на `#fff` либо зафиксировать
   границу светлоты акцента в `DESIGN.md`.
3. **Границы полей ввода** – поднять альфу с `0.25` до `0.50`.
4. **Индикатор в админке** – затемнить и добавить текстовую подпись.

## Что в эту проверку не входило

Проверялся только контраст (1.4.3, 1.4.11) – по постановке задачи. Не проверялись
и требуют отдельного прохода: порядок фокуса и доступность с клавиатуры (2.1.1,
2.4.3), объявление элементов скринридером (4.1.2), размеры сенсорных мишеней
(2.5.5), альтернативы к изображениям (1.1.1), поведение при зуме 200 %.
